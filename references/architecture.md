# Architecture evidence

Inspected 2026-10-23. This is source inspection, not a model execution or an independent benchmark. The deck's AutoTrust walkthrough is pinned to [`autotrust/JEV-27B@14b425269ed24452e0a5ad5a8f3e51d139647a88`](https://huggingface.co/autotrust/JEV-27B/tree/14b425269ed24452e0a5ad5a8f3e51d139647a88). Later AutoTrust models are outside this walkthrough.

## What the files establish

- [config.json](https://huggingface.co/autotrust/JEV-27B/blob/14b425269ed24452e0a5ad5a8f3e51d139647a88/config.json): `Qwen3_5ForCausalLM`, hidden dimension 5,120, 64 decoder layers, with three linear-attention layers followed by one full-attention layer. The architecture class is not the marketing/model identifier: the release identifies its backbone as Qwen3.8-27B.
- [judge_config.json](https://huggingface.co/autotrust/JEV-27B/blob/14b425269ed24452e0a5ad5a8f3e51d139647a88/judge_config.json): 24 native slots, partitioned as Noul [0,2), Score [2,8), Choice [8,24). They correspond to false/true, six ordered levels, and A–P. Weights are marked unmerged; the language-model head is retained.
- [adapter/adapter_config.json](https://huggingface.co/autotrust/JEV-27B/blob/14b425269ed24452e0a5ad5a8f3e51d139647a88/adapter/adapter_config.json): rank 16, alpha 32, dropout 0.05; adaptation targets attention, linear-attention and MLP projections. This is an adapter configuration, not evidence that TypeSafe uses LoRA.
- [serve_decide.py, lines 71–72](https://huggingface.co/autotrust/JEV-27B/blob/14b425269ed24452e0a5ad5a8f3e51d139647a88/serve_decide.py#L71): vLLM is asked for one token's log probabilities. Thus “no autoregressive answer loop” is accurate; “the server never requests a token” is not.
- [serve_decide.py, lines 242–255](https://huggingface.co/autotrust/JEV-27B/blob/14b425269ed24452e0a5ad5a8f3e51d139647a88/serve_decide.py#L242): the prompt includes kind, state, question and runtime option text. Selected token log probabilities receive slot bias and are divided by the temperature for that kind before softmax. The shared vocabulary normalizer cancels when renormalizing these selected logits.
- [calibration.json](https://huggingface.co/autotrust/JEV-27B/blob/14b425269ed24452e0a5ad5a8f3e51d139647a88/calibration.json): temperatures approximately 1.0143 / 1.0161 / 1.0036 for Noul / Choice / Score; 10,954 fit rows. These are fitted values for this release and data, not universal constants.
- The HTTP server extends Choice to 256 labels. Only the first 16 use the trained Choice head rows; subsequent labels use existing vocabulary rows with zero added bias. Do not draw a 256-slot trained classifier. The default Qwen strategy is a single readout; optional permutation/tournament strategies add passes. See [lines 245–279](https://huggingface.co/autotrust/JEV-27B/blob/14b425269ed24452e0a5ad5a8f3e51d139647a88/serve_decide.py#L245).

## What the publisher reports

The [pinned model card](https://huggingface.co/autotrust/JEV-27B/blob/14b425269ed24452e0a5ad5a8f3e51d139647a88/README.md) describes a frozen Qwen3.8-27B text backbone, a trained adapter and 24-slot linear head, and an unchanged generation head. Decision requests enable the adapter; generation requests disable it. The vLLM export expresses the decision head through vocabulary-head LoRA rows. The publisher reports 108.8 million adapter parameters and 123 thousand head parameters, with head shape 24 × 5,120 plus bias.

Training reportedly distills public teacher distributions with KL divergence, adding a ranked-probability objective for Score. This is not TypeSafe's unpublished RLCD procedure. Low KL measures imitation, including teacher errors; it does not establish correctness against human labels. The model card identifies the project as independent of TypeSafe. Its benchmark and latency figures remain publisher reports, not measurements made for this presentation.

## Suggested progressive diagram

1. State + question + options → tokenization → frozen decoder backbone → final hidden state.
2. Add decision-only adapters inside that backbone → 24-slot projection → select active slots → temperature → probability distribution.
3. Add a second route: adapters off → original vocabulary head → repeated next-token generation.

This diagram is specific to the inspected AutoTrust release. A similar diagram for TypeSafe must be labeled **proposed internals**, not inspected implementation. Runtime labels are supplied in text; the fixed slot meanings are positional, not fixed business categories. Separate questions can share a state prefix in supporting runtimes, but shared computation and independence are distinct claims.

These projects have different prompts, limits, training and return schemas. An interface adapter does not make their probabilities interchangeable. Laya's use of the term RLCD does not reveal TypeSafe's training recipe.

## Calibration → LoRA → decision heads (added 2026-10-23)

The six slides after speculative questions develop an educational progression, not a claim about TypeSafe's private architecture or the chronological training order in AutoTrust. The first readout illustration, bias/temperature arithmetic, and teacher/student bars are constructed examples, not captures. No model was run for these slides.

- Raw-probability illustration: [0.97, 0.01, 0.01, 0.01]. The calibration question concerns repeated predictions on comparable data, not whether this single dividend decision is correct.
- Temperature arithmetic: scores [2 ln(7),0,0,0], zero bias. T=1 gives [49/52,1/52,1/52,1/52], displayed as94/2/2/2 percent; T=2 gives exactly70/10/10/10 percent. The separate SVG shows61 token positions with scores −x²/32 for integer x from−30 to30, normalized by softmax at T=1 and T=2; it illustrates a wider token distribution, not the four-option example. The bias example separately changes A's score from4 to3. A common scalar bias cancels under softmax; class/slot-specific biases need not preserve argmax.
- [Zhao et al., 2021](https://arxiv.org/abs/2102.09690) establishes prompt/answer biases and contextual calibration, not a claim that all modern LLMs are overconfident. [Guo et al., 2017](https://arxiv.org/abs/1706.04599) supplies the temperature-scaling foundation. High concentration alone is not evidence of miscalibration.
- SemIf [method](https://github.com/TheoLeeCJ/SemIf-OpenJev/blob/23cf1f39fc9534fe81437200959b6dfc7106e45a/docs/CALIBRATION.md), [code](https://github.com/TheoLeeCJ/SemIf-OpenJev/blob/23cf1f39fc9534fe81437200959b6dfc7106e45a/benchmarks/calibrate.py), and [WANLI artifact](https://github.com/TheoLeeCJ/SemIf-OpenJev/blob/23cf1f39fc9534fe81437200959b6dfc7106e45a/results/raw/calibration/wanli256.json): temperature only, hard-label NLL minimized by golden-section search over [0.05,20]; five group-disjoint folds. WANLI256 raw ECE0.20841294 → out-of-fold ECE0.06909064, accuracy0.63671875 unchanged. ECE uses top-choice confidence and ten equal-width bins. Shipped T2.49903087 is fit on all256 rows; OOF evaluation uses fold-specific temperatures. These are publisher artifacts, not our measurements or cross-domain guarantees.
- AutoTrust's bias is the learned decision head intercept, not a separately documented post-hoc bias fit. Its per-kind temperatures are fit after training by L-BFGS on10,954 calibration rows. Near-one temperatures describe the trained model, not the raw backbone.
- [LoRA](https://arxiv.org/abs/2106.09685) diagram uses W[out,in], A[r,in], B[out,r]; y=Wx+(alpha/r)BAx. The diagram depicts one adapted projection; actual target modules and rank/alpha come from the pinned adapter config above.
- AutoTrust's head starts from vocabulary rows for false/true,0–5,A–P, then learns24×5120 weights plus24 biases jointly with LoRA. Native head parameters:122,904. Runtime option meanings are in the prompt; A is not inherently Business. The slide covers native slots, not the256-option serving extension. The original vocabulary head remains available for generation with the adapter disabled; the vLLM export represents the specialized rows through vocabulary-head LoRA.
- Training-distribution example target[.70,.10,.15,.05], student[.90,.03,.05,.02]. Both argmaxBusiness, but KL(target||student)>0. AutoTrust reports KL distillation plus0.5×ranked-probability score for Score. Its teacher mixture includes TypeSafe distributions, programmatic labels and downweighted placeholder labels, detailed in the pinned model card. Evaluating against independent outcome labels is the engineering recommendation, not a claim that teacher imitation proves truth. This recipe is distinct from TypeSafe's unpublished RLCD.

The AutoTrust overview inserted after Open Implementations uses the same pinned sources. Repeated attention/feed-forward tiles summarize adapters distributed through the64-layer hybrid decoder; they are not a literal three-layer architecture. Red A–D slots illustrate selection for the existing four-option prompt. Final bars use the conceptual distribution[.70,.10,.15,.05], not a captured output. The diagram presents the logical native decision head (including its learned bias); the vLLM export implements this through modified vocabulary rows as documented above.

The revised LoRA overview uses a perspective illustration of frozen matrices and one small red tile representing the adapters collectively; their area is not a parameter-count scale. The adapters operate throughout attention/feed-forward projections, not as a final appended layer. The slide's108M is a coarse shortened figure for the published108.8M adapter parameters (approximately0.4% of the backbone). Rank16 and two-factor updates are unchanged; the decision head is separate from this parameter count.
